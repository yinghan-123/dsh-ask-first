## 2026-10-24 18:40 首次安装

### 起因
用户反馈：DSH 内核自带的 `ask_user_question`（`@deepseek-ai/dsh-user-questions` +
`@deepseek-ai/dsh-tool-ask-user` + `@deepseek-ai/dsh-client-ui-user-questions`）能力没问题，
**但模型不主动用**——"AI 会擅自做主，不主动向用户提问"。

所以本插件补的不是工具，是**行为层**。

### 安装位置
- 包：`profiles/ondevice/node_modules/dsh-ask-first/`
- profile：`profiles/ondevice/package.json` 的 `dsh.profile.bundles` 追加 `dsh-ask-first`
- 备份：同目录 `安装备份-20261024-184011/`（package.json + cordis.patch.yml）

### 激活结果（实测，未重启）
| 检查项 | 结果 |
| --- | --- |
| Loader 行 | `include:ask-first` / `dsh-ask-first` / `patchId: ask-first` |
| fiberPhase | `active` |
| 系统提示 section | 已出现在下一次请求的 system prompt（`# 先问后干（ask-first）` 段） |
| 设置页表单 | 由 `Config` 的 volatile 字段自动投影为「设置 → 插件 → ask-first」 |

DSHM 的 loaders 在 profile patch 变化时做了 reconcile（`app-boot/config-reload`），
本插件因此**无需重启应用**即可挂载。

### 回滚
1. 从 `profiles/ondevice/package.json` 的 `dsh.profile.bundles` 删掉 `dsh-ask-first`；
2. 或直接在「设置 → 插件 → ask-first」把总开关关掉（纪律段与提醒立即停止注入）；
3. 彻底删除：删掉 `node_modules/dsh-ask-first/` 目录。

### 已知边界
- 变更性操作的判定是启发式：结构性工具走白名单，`bash`/`python` 走参数特征匹配；
- 子代理的调用由父代理负责，硬闸只约束根代理。

## 2026-10-24 20:2x v1.2.0：设置界面（浏览器半部）

### 先更正上一轮的一个错误判断
上一轮写「重启后设置页会出现 6 项配置」。**这是错的**：DSH 的「设置 → 插件」页只渲染
**官方插件的 companion 页面**；第三方 bundle 的 volatile `Config` 虽然会进 settings 服务的
schema，但**没有地方渲染它**。

真实机制见 `dsh-python-only/lib/client.js` 的头注：第三方插件的配置页必须由包**自己的浏览器
半部**注册到 slot 上。所以要让 ask-first 有设置界面，必须写 client 半部。

### 本版做了什么
- 新增 `lib/client.js`（手写、无构建步骤、`window.__ModuleLoader__.load` 协议，
  与 `dsh-python-only` / `dsh-meme` 同款）；

- 页面内容：总开关、硬闸开关、提醒阈值、三份工具名单（已提问 / 计入变更 / 硬闸拦截）、
  保存与恢复默认；
- 数据全走 `ctx.configForms.get("ask-first")` 的公开面
  （`getSnapshot` / `subscribe` / `set` / `unset`），写入即热更新运行中的 host 实例；
- `package.json`：`version 1.2.0`、`exports["./client"]`、
  `dsh.client = { platform: "web", inject: ["@deepseek-ai/dsh-client-ui-settings"] }`。

## 2026-10-24 20:1x v1.3.0：每次请求都注入提醒

用户要求：「每次 AI 回答时都要注入提醒提示词」。

### 理解与实现
「每次回答」= 每个模型请求（一次 step 结束要么调工具、要么给最终回答）。所以用
`systemPrompt.context()` 注册一条**每步重算**的常驻提醒：

```js
promptCtx.systemPrompt.context({
  name: 'app:ask-first-reminder',
  order: 130,
  text: () => liveEnabled(config) && liveAlwaysRemind(config) ? standingReminderText() : ''
});
```

- runtime context 每步重算并渲染进快照，总在模型注意力的最近位置 —— 长会话里
  system prompt 前段的纪律段会衰减，这条不会；
- 文本**固定**（不带计数），不破坏 prompt 缓存；约 100 字/请求；
- 新增配置 `alwaysRemind`（默认 true），设置页与总开关、硬闸开关并列。

### 同时处理
用户还要求删除 `.ask-first-selfcheck.py` 临时副本。硬闸先拦了一次（用户消息只说「删除」，
没点名文件名，`authorizedByUserText` 不认指代）→ 按规则 `ask_user_question` 确认 →
用户选「删除」→ 重试放行 → 已删除。**这是硬闸完整闭环的第一次真实走通**。

### 验证
| 检查 | 结果 |
| --- | --- |
| 静态自检：host 865 行 + client 564 行（含 `systemPrompt.context`、`alwaysRemind`、`standingReminderText`） | 通过 |
| 硬闸闭环（拦 → 问 → 放行） | 通过，临时文件已删 |
| `systemPrompt.context` 注册 | 待重启后观察：每个请求的 runtime context 末尾应出现「提醒（ask-first）：……」 |

### 需要做的事
**重启一次 DSHM**（host 半部改了 `lib/index.js`，Node 的 ESM 模块缓存不会重新执行同一
specifier；顺带把上次的 client 半部也一起加载了）。重启后：
1. 设置侧栏出现「先问后干」；
2. 每个请求里都能看到常驻提醒。

## 2026-10-24 20:2x v1.4.0：常驻提醒改成「硬规则」，且正文可编辑

用户选择「让注入内容更强硬」。

### 改动
- `DEFAULT_STANDING_REMINDER`：从「提醒：……先在回复里说清」改为**硬规则**口吻——
  三条短规则（必须 / 不得 / 禁止）：
  1. 用户该拍板的事必须先 `ask_user_question`，拿到回答前不得擅自执行、也不得先做了再解释；
  2. 禁止用「我假设…」「默认按…处理」「先做再说」绕过确认；
  3. 本轮已授权的范围可以自行决定，但不得外扩。
- 新增配置 `standingReminder`（string，volatile）：**整个提醒正文可在设置页改写**，
  留空则用内置默认。这样以后调语气/措辞不用改代码、不用重启。
- 设置页「常驻提醒」卡片里加了多行编辑框（保存时写入；清空 = 恢复内置默认）。

## 2026-10-24 22:0x v1.5.0：按调研结论收紧硬闸

来源：[调研-同类机制.md](./调研-同类机制.md)。改三条，全部来自同类实现的直接对照。

### ① 自建对象免授权（auto-review 的 low 规则 / decision-gate 的 `.agent-scratch` 豁免）
- `tools/post-execute` 里记录本会话 `write` 写过的路径（`WeakMap<agent, Set<path>>`）；
- 硬闸遇到 `remove`/`move` 且目标路径**完全相等**时放行；
- 只认 `write`（`edit` 的对象可能是用户既有资产），不做 basename 匹配；
- 新增配置 `selfCreatedExempt`（默认 true），设置页有独立开关。

### ② 收紧授权语义（`dsh-user-approval` 的 grants 语义）
- 原实现：本回合调用过 `ask_user_question` → 全部硬闸放行（问个无关问题就能解锁）；
- 新实现：记下这次提问的**正文**（问题 / 标题 / 每个选项的 label 与 description），
  放行要求正文里点到本次操作的目标；
- 新增 `askedText()` / `askedCoversTargets()`。

### ③ UNKNOWN 即确认（OpenHands 的「不知道 ≠ 安全」）
- 名单内的工具若 `collectTargets(参数)` 为空（读不出目标），直接拒绝，不进入任何放行通道；
- 新增 `unknownTargetText()` 文案，要求模型把目标写进参数并先问用户。

### 验证
| 检查 | 结果 |
| --- | --- |
| 静态自检：host 1088 行 + client 611 行 | 通过 |
| 规则用例表（10 条，Python 等价移植） | 全部通过 |
| 关键用例 | 删自建文件→放行；删他人文件→拦；提问点到目标→放行；**提问没点目标（旧漏洞）→拦**；用户点名→放行；泛说清理→拦；参数无目标→UNKNOWN 拦 |

  （同步方法，服务缺失或抛错返回 undefined）；

- 新增配置 `respectSandboxMode`（默认 true），设置页第 5 个开关。
- 注意：DSHM 端侧当前是 `danger-full-access`，所以这条**在本机不会触发**，只在切到只读模式
  时生效。它是为「换环境/换权限档位」准备的正确性，不是本机行为变化。
